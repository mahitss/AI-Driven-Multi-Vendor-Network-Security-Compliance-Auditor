# NetVigil Platform Operations & User Manual
**AI-Driven Multi-Vendor Network Security Compliance Auditor**  
*Problem Statement ID: SIH26155 | Organization: National Technical Research Organisation (NTRO)*

---

## 1. Executive Summary & Core Principle

NetVigil is an enterprise-grade cybersecurity compliance and risk intelligence platform designed for critical national infrastructure and multi-vendor networks. It eliminates the ambiguity, manual effort, and hallucination risks associated with auditing heterogeneous network infrastructure.

### The Immutable NetVigil Invariant
```
                      ┌─────────────────────────────────────────┐
                      │             NETVIGIL CORE               │
                      │                                         │
                      │         AI CAN EXPLAIN.                 │
                      │         AI CANNOT DECIDE.               │
                      └─────────────────────────────────────────┘
```
1. **100% Deterministic Compliance Verdicts**: Every `PASS` / `FAIL` decision is computed by deterministic Abstract Syntax Tree (AST) parsing and rule evaluation.
2. **Line-Level Evidence Provenance**: Every finding links directly to verbatim configuration line numbers with cryptographic SHA-256 integrity.
3. **Derived & Explainable Risk**: Risk scores are calculated mathematically from active findings and severity weights—never estimated or generated by an LLM.
4. **Zero-Automated Network Execution**: Remediations are strictly reviewable CLI diffs. No automated network push or blind SSH execution.

### Module 1: Security Posture Overview (`/` & `/dashboard`)
- Real-time enterprise compliance posture score across all ingested infrastructure.
- High-level KPI metric cards: Total Monitored Devices, Monitored Frameworks (CIS, NIST, DISA STIG, ISO 27001), Active Risk Score (0–100), Total Open Findings.
- Multi-framework compliance score distribution and severity breakdown charts.
- Historical compliance trend tracker and audit session log.

### Module 2: Security Operations Command Center (`/operations`)
- Live 3-column Security Operations Center (SOC) workspace.
- **Operational Spine**: Visual tracking of `SIGNAL → EVENT → DETECTION → FINDING → RISK → EVIDENCE → REMEDIATION`.
- Real-time audit activity feed with device, vendor, and severity filters.
- Grounded `ASK NETVIGIL` operational advisory pane.

### Module 3: Multi-Vendor Security & 3D Convergence Terrain (`/multi-vendor`)
- Interactive 3D "Security Convergence Terrain" with smooth Orbit Drag & Zoom controls.
- Visualizes heterogeneous syntax ingestion (Cisco IOS West peak, Juniper JunOS North peak, Fortinet FortiOS East peak) converging into the central **Universal Security Model (AST Normalization)** summit.
- Downstream compliance ridge mapping normalized facts to 4 standard frameworks.
- Interactive hover tooltips citing exact AST line numbers and configuration evidence.

### Module 4: Configuration Intelligence & Real E2E Pipeline (`/configurations`)
- Multi-vendor configuration ingestion (`.cfg`, `.conf`, `.txt`, `.log`).
- Signature-based vendor detection (Cisco, Juniper, Fortinet) with confidence scoring.
- Line-preserving AST parsing and Universal Security Model fact extraction.
- **Real End-to-End Analysis Pipeline**: Interactive execution modal demonstrating raw configuration ingestion, AST parsing, control evaluation, evidence mapping, derived risk calculation, and real re-analysis turning `FAIL` into `PASS`.

### Module 5: Evidence Explorer (`/findings`)
- Comprehensive finding repository filtered by framework (CIS, NIST, STIG, ISO), severity (Critical, High, Medium, Low), and status.
- Direct verbatim configuration line citations with clickable drawer inspection.
- Expected vs. Actual property values.

### Module 6: Risk Intelligence Workspace (`/risk`)
- Deterministic risk engine correlating evidence-backed findings into prioritized exposures.
- Priority classification: **P0** (Immediate Danger $\ge 90$), **P1** (High $\ge 75$), **P2** (Medium $\ge 50$), **P3** (Low $< 50$).
- Interactive Risk Relationship Graph linking assets, CVEs, attack paths, and affected controls.
- Explainable formula breakdown display (e.g., *"Calculated from 4 findings: 2 HIGH, 1 MEDIUM, 1 LOW"*).

### Module 7: Remediation Center (`/remediation`)
- Catalog of verified, allowlisted vendor CLI remediation templates.
- Side-by-side visual diff previews (`REMOVE [-]` non-compliant baseline / `ADD [+]` compliant directive).
- Human-in-the-loop approval workflows with verified CLI copy & export actions.
- Zero Automated Network Execution Policy enforcement.

### Module 8: Multi-Framework Compliance Auditor (`/compliance/cis`, `/nist`, `/stig`, `/iso`)
- Dedicated audit interfaces for:
  - **CIS Benchmarks** (CIS Cisco IOS 17, Juniper JunOS, FortiOS benchmarks)
  - **NIST SP 800-53 Rev 5** (AC-17, SC-8, IA-2, AU-2, etc.)
  - **DoD DISA STIG** (Network Infrastructure STIG)
  - **ISO/IEC 27001:2022** (Control A.9, A.12, A.13, etc.)
- 100% deterministic rule evaluations.

### Module 9: AI Boundary & Assistant (`/ai-boundary` & `/ai-assistant`)
- Dedicated architecture interface proving the strict boundary between deterministic security and advisory AI.
- Context-grounded AI assistant: Answers technical questions based strictly on active audit session evidence.
- 1-click grounded explanations for complex compliance failures.
- Prompt injection immunity and credential redaction filters.

### Module 10: Adaptive Learning & Syntax Training (`/adaptive-training`)
- Handles unparsed, proprietary, or custom vendor CLI commands without backend code modifications.
- Human-in-the-loop workflow: AI suggests candidate property mappings $\rightarrow$ checked against strict property allowlist $\rightarrow$ Security Administrator reviews, accepts, or rejects $\rightarrow$ persisted to database with full audit trail.

### Module 11: Devices & Inventory Management (`/devices`)
- Multi-vendor network asset inventory (Routers, Switches, Firewalls, Gateways).
- Device posture scores, operating system platforms, firmware versions, IP addresses, and configuration history.

### Module 12: Executive Audit Reports (`/reports`)
- Printable, official compliance audit certificates and executive reports.
- Framework breakdown, severity distributions, executive sign-off lines, and official metadata.

## 3. What You Have To Do: Setup & Execution Guide

### Prerequisites
- **Python 3.11+** (Python 3.13 recommended)
- **Node.js 20+** (Node.js 22 LTS recommended)
- **pnpm** or **npm**

---

### Step 1: Start the Backend (FastAPI)

Open a terminal in the project root:
```bash
# Activate python virtual environment
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# Install python dependencies (if not already installed)
pip install -r apps/api/requirements.txt

# Start the FastAPI server with reload
cd apps/api
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```
The backend is now live at:
- **API Base**: `http://127.0.0.1:8000`
- **Interactive Swagger Docs**: `http://127.0.0.1:8000/docs`
- **Alternative ReDoc**: `http://127.0.0.1:8000/redoc`

---

### Step 2: Start the Frontend (Next.js)

Open a second terminal in the project root:
```bash
# Navigate to web application
cd apps/web

# Install dependencies (if needed)
pnpm install # or npm install

# Start Next.js development server
pnpm run dev # or npm run dev
```
The frontend is now live at:
- **Web Application**: `http://localhost:3000`

---

### Step 3: Run Full Automated Verification Suite (109 Tests)

To verify that all deterministic parsers, compliance engines, risk calculators, AST normalizers, and API routes are 100% operational:
```bash

.venv\Scripts\pytest.exe -v
```
**Expected Result**: `109 passed in ~7.5s`

## 4. Step-by-Step Operational Workflows (How To Use NetVigil)

### Workflow 1: Running the Real End-to-End Security Analysis Pipeline

This is the canonical demonstration of NetVigil's core capability:

1. Open your browser to `http://localhost:3000/configurations`.
2. In the top right header, click the cyan button **`[ REAL E2E PIPELINE ]`**.
3. In the modal, click **`[ EXECUTE REAL PIPELINE ]`**.
4. Observe the 4 real deterministic steps execute with live feedback:
   - **1. Ingestion**: Ingests real Cisco IOS configuration (`EDGE-RTR-01`), computes SHA-256.
   - **2. AST & Facts**: Line-preserving parser normalizes 18 security properties.
   - **3. Controls**: Zero-LLM evaluator checks CIS/NIST rules (`CIS-1.2.1` fails due to `ip ssh version 1`).
   - **4. Derived Risk**: Risk score calculated formulaically (e.g. `42.0 / 100`).
5. **Inspect the Evidence**:
   - In the findings list, click **`CIS-1.2.1`** (Ensure SSH Version 2 is enabled).
   - View the **Actual Configuration**: `Line 17: ip ssh version 1` highlighted in red.
   - View the **Remediation Proposal**: `ip ssh version 2`.
   - Click **`View Full Config`** to inspect the entire raw file with Line 17 highlighted.
6. **Execute Re-Analysis**:
   - Click the green button **`[ APPLY FIX & RE-ANALYZE ]`**.
   - NetVigil replaces `ip ssh version 1` with `ip ssh version 2`, re-parses the AST, and re-evaluates the controls.
   - Watch `CIS-1.2.1` transition from **`FAIL` $\rightarrow$ `PASS`** with a verified transition banner.
   - Observe the risk score recalculate downward!

---

### Workflow 2: Multi-Vendor Equivalence Demonstration

To prove cross-vendor AST normalization (Cisco vs. Juniper vs. Fortinet):

1. Navigate to `http://localhost:3000/multi-vendor`.
2. Inspect the **3D Security Convergence Terrain**:
   - Click and drag to orbit and rotate the 3D topography in 360°.
   - Scroll your mouse wheel to zoom in and out.
   - Hover over the **Cisco IOS**, **Juniper JunOS**, or **Fortinet FortiOS** summits to illuminate their AST transformation pipelines.
   - Hover over the **`EVIDENCE: [LINE 17]`** node to view the provenance tooltip.
3. On the left panel, click between the vendor tabs (**Cisco IOS-XE**, **Juniper JunOS**, **Fortinet FortiOS**):
   - Notice how all three distinct vendor syntaxes normalize to the identical Universal Security Model property (`remote_access.ssh_version = 2`).
   - Notice how the exact same rule (`CIS-1.2.1` / `NIST AC-17`) evaluates across all three vendors with identical mathematical consistency.

---

### Workflow 3: Evidence Explorer & Finding Line Citations

To trace findings back to raw source lines:

1. Navigate to `http://localhost:3000/findings`.
2. Filter findings by framework (e.g., **CIS Benchmark** or **NIST SP 800-53**).
3. Filter by severity (**CRITICAL**, **HIGH**, **MEDIUM**, **LOW**).
4. Click on any non-compliant finding card.
5. In the drawer/detail view:
   - View the exact verbatim configuration line number.
   - View the raw command text as captured in the device config.
   - Click **`Explain Finding (AI)`** to receive a grounded, read-only explanation strictly bounded by the evidence.

---

### Workflow 4: Reviewing Risk Intelligence & Priority Exposures

To understand exposure priorities:

1. Navigate to `http://localhost:3000/risk`.
2. Inspect the priority breakdown (**P0 Critical**, **P1 High**, **P2 Medium**, **P3 Low**).
3. Review the **Calculated Risk Score** and formula explanation.
4. Interact with the **Risk Relationship Graph** to see how non-compliant findings map to assets, threat vectors, and control families.

---

### Workflow 5: Generating Safe Remediation CLI Diffs

To safely review and export remediation commands:

1. Navigate to `http://localhost:3000/remediation`.
2. Select a non-compliant finding.
3. Inspect the side-by-side CLI diff:
   - Lines with `[-]` represent non-compliant directives to be removed.
   - Lines with `[+]` represent compliant directives to be applied.
4. Click **`Copy CLI Fix Script`** or **`Export Script`** to prepare the verified script for authorized change-window deployment.

---

### Workflow 6: Adaptive Learning for Unknown Directives

To teach NetVigil new or proprietary syntax without changing code:

1. Navigate to `http://localhost:3000/adaptive-training`.
2. View unparsed directives discovered during configuration ingestion.
3. Click **`AI Syntax Interpretation`** to analyze the unknown directive.
4. Review the candidate Universal Security Model property suggested by AI.
5. Notice the **Allowlist Guard**: NetVigil ensures the property strictly belongs to the trusted security schema.
6. Click **`Accept & Persist Mapping`** or **`Reject`**. Once accepted, the new mapping is permanently stored in SQLite and immediately active for all future audits.

---

### Workflow 7: Generating Executive Compliance Reports

To print or export official compliance documentation:

1. Navigate to `http://localhost:3000/reports`.
2. Select the desired device and audit session.
3. View the comprehensive report containing:
   - Official NTRO & SIH26155 metadata.
   - Overall compliance percentage and letter grade.
   - Per-framework score breakdown (CIS, NIST, STIG, ISO).
   - High-severity finding log with exact line evidence.
   - Executive sign-off lines.
4. Click **`Print / Save PDF`** (`Ctrl+P`) for an official print-optimized document.

## 5. Summary API Reference

All endpoints are fully authenticated and documented in the interactive Swagger UI (`http://127.0.0.1:8000/docs`).

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/v1/analysis/ingest` | Ingest raw configuration, detect vendor, extract AST facts |
| `GET` | `/api/v1/analysis/{id}` | Get complete status, evaluated controls count, and derived risk |
| `GET` | `/api/v1/analysis/{id}/findings` | Get deterministic findings with exact configuration line citations |
| `GET` | `/api/v1/analysis/{id}/evidence` | Get all extracted facts mapped to configuration lines |
| `GET` | `/api/v1/analysis/{id}/risk` | Get derived risk score and formula breakdown |
| `POST` | `/api/v1/analysis/{id}/reanalyze` | Re-evaluate modified config and verify FAIL $\rightarrow$ PASS |
| `GET` | `/api/v1/analysis/{id}/configuration` | Get raw configuration text with numbered lines |
| `POST` | `/api/v1/audits` | Execute multi-framework compliance audit |
| `GET` | `/api/v1/audits` | List all historical audit sessions |
| `GET` | `/api/v1/devices` | List all monitored multi-vendor network devices |
| `GET` | `/api/v1/overview/posture` | Get high-level enterprise posture metrics |
| `GET` | `/api/v1/training/unparsed` | Get unparsed CLI directives for adaptive learning |
| `POST` | `/api/v1/training/mappings` | Submit human-reviewed syntax mapping to knowledge store |
| `POST` | `/api/v1/ai/explain/finding` | Get grounded advisory explanation for finding |
| `GET` | `/health` & `/api/v1/health` | Service health, database status, latency check |
